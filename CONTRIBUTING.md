# Contributing

PRs are welcome. Open an issue first.

The issue is where scope gets agreed: what is wrong, what would fix it, whether it belongs in this repo. Once that is settled, a PR that references the issue is usually merged quickly. Unannounced PRs may sit.

Corrections to data are the most useful kind of contribution: a wrong readiness score in [research](https://github.com/envisioning/research), a stale indicator in [national-capability-benchmark](https://github.com/envisioning/national-capability-benchmark), a misjudged signal in [signals-benchmark](https://github.com/envisioning/signals-benchmark). Cite the source.

Keep PRs small and single-purpose. Match the style of the surrounding code. Each repo's README or AGENTS.md says how to build and test it.

Security issues go to contact@envisioning.com, not the tracker. See [SECURITY.md](SECURITY.md).
